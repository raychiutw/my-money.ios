# 按鈕一律不填色:作廢 ADR-0007 的單色填滿,套用中的篩選與選取狀態用品牌粉紅

ADR-0007(0.5.0)把互動元素單色化:主要動作是單色填滿的玻璃膠囊、sheet 的 ✓ 是單色填滿圓鈕、選取的分類格反白填滿、套用中的篩選是反白實心圓。使用者在真機看過之後明確要求:**按鈕類一律不要底色,背景跟主題底色同色**(淺色白底、深色黑底),只留玻璃外框。這則 ADR 誠實記錄這個修正:ADR-0007 的這三條判斷,在真機上不成立。

## Considered Options

- **維持單色填滿**:使用者看過了不要。
- **改成品牌粉紅填滿**:ADR-0007 就是為了擺脫「每種按鈕多一個特例字色」才單色化,粉紅填滿會把特例帶回來。
- **不填色、只有玻璃外框**(採用):`.glass` 樣式四種外觀(淺色、深色、增強對比各一)都正常,不需要特例字色;主要動作靠**粗體字與位置**區分,不靠反白。

## Consequences

- **作廢 ADR-0007 的三條**:「主要動作單色填滿的玻璃膠囊」「✓ 單色填滿圓鈕」「選取格反白」。其餘維持:互動色單色(accent 黑白)、沒有裸文字按鈕、sheet 的 ✕ 與 ✓、區塊標題的「…」沒有外框、玻璃只給控制層。
- 主要動作膠囊(登入、註冊、建立、加入、ATM 提款／轉帳、購買力試算)是 `.glass`、字粗體,不再用 `.glassProminent`,也就不再需要「明確指定反色字」的特例。
- Sheet 的 ✓ 跟 ✕ 是同一種玻璃圓鈕,靠勾勾與 VoiceOver 標籤區分。實測:`role: .confirm` 與 `.confirmationAction` 兩個在 iOS 26 都會自動畫成 accent 填滿,所以 ✓ 放在 `.primaryAction`、不加 `role: .confirm`。
- **品牌粉紅的使用範圍擴大**:logo、App icon、頭像、目前所在的 tab(ADR-0007),**加上套用中的篩選與選取狀態**。顏色是 `Color.brandPink`(淺色 `#B8434D`、深色 `#FF8A8A`、增強對比 `#9E2F3A`／`#FFB3B3`)。
  - 套用中的篩選:圖示從反白實心圓改成**粉紅的空心圓圈**(`line.3.horizontal.decrease.circle` 加粉紅);沒套用時維持一般圖示。粉紅是狀態色,所以不只靠顏色:圓圈的有無也能分辨。
  - 選取狀態:選取的外框與勾勾是粉紅,不填色。分類格是 3pt 粉紅外框加粉紅勾勾(字與圖示維持原色);儲蓄目標的 emoji 是粉紅外框;選帳戶清單、歸屬、類型這類內嵌選擇列的勾勾是粉紅(`.tint(.brandPink)`)。
  - **做不到的:視角與帳戶檢視範圍的系統選單,勾勾維持系統樣式。** 試過 `.tint(.brandPink)`:選項前面的符號(地球、房子、鎖)變粉紅,勾勾還是白色——系統選單的勾勾不吃 tint。為了這個自己重做選單不值得,所以維持系統樣式,不加 tint(不然符號變粉紅,反而偏離「選項前的符號不變」)。分段控制是系統畫的,也維持系統樣式。
- 停用狀態字與外框變淡(系統處理)。語意色(收入綠、支出紅)、頭像、目前所在 tab 的粉紅、玻璃工具列不受影響。
- 測試:像素測試反轉——玻璃按鈕中央沒有大面積反白(深色白色占比低、淺色黑色占比低)、玻璃圓鈕有外框、字看得到;套用中的篩選有粉紅像素、沒套用沒有;選取的分類格有粉紅外框、沒選的沒有。
- 上游 web 的視覺不變,這是互動層的 HIG 轉譯,不影響功能對等(`docs/parity.md` 沒有新增項目)。
