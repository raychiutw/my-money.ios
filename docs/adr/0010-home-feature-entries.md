# 首頁改成重點數字加功能入口格,規劃從「我的」搬到首頁

> **後續修訂**:[ADR-0011](0011-home-entries-only-tabless-features.md) 把入口縮成 3 格(tab 已有的功能不放)。
>
> **部分取代 [ADR-0004](0004-family-tab-planning-in-me.md)**:規劃(週期收支、儲蓄目標、現金流預測)不再收在「我的」的第二個分頁;「我的」只剩設定。tab 仍是總覽、記帳、帳戶、家庭、統計五個。

週期收支、儲蓄目標、現金流預測在「我的」的「規劃」分頁裡,要點頭像、切分頁、再點項目,三層深;新使用者幾乎找不到。首頁原本是一串區塊(數字、帳戶、最近交易、目標),除了數字之外沒有指向其他功能。web 的總覽另有幾項 iOS 當初為了精簡刻意拿掉的資訊(三格數字的組成明細、信用卡代墊與未出帳),使用者現在要求放回來。

## Considered Options

- **維持「我的」的規劃分頁,只加個別捷徑**:入口重複,「我的」仍是設定與功能混在一起。
- **規劃升為第六個 tab**:tab 超過五個會出現「更多」溢位(ADR-0004 的理由仍成立)。
- **首頁加一列文字連結**:HIG 不鼓勵裸文字按鈕(ADR-0007),而且沒有地方放關鍵數字。
- **圖示加名稱加一個關鍵數字的入口格**(採用):入口本身就是摘要,不點進去也知道大概狀況。

## Decision

- 首頁由上而下:主視覺(淨可用餘額、它的組成一行、30 天走勢)、三格數字(各帶兩行組成明細)、超支提示、**功能入口格**、帳戶卡片。「最近交易」「目標圓環」拿掉,由「記帳」「儲蓄目標」入口取代。
- 入口共 8 格,順序固定:記帳、帳戶、信用卡、家庭、統計、週期收支、儲蓄目標、現金流預測。每格一個關鍵數字,全部是後端的既有值,client 不重算:記帳=本月筆數、帳戶=帳戶數、信用卡=待繳總額、家庭=分攤建議、統計=當月支出、週期收支=每月平均、儲蓄目標=已存與整體達成率、現金流預測=最低餘額與日期。
- 入口去哪:記帳、帳戶、信用卡、家庭、統計切到對應的 tab(信用卡和帳戶都到帳戶頁);週期收支、儲蓄目標、現金流預測在總覽的導覽堆疊 push。
- **每一項關鍵數字獨立失敗**:本月筆數、家庭分攤、儲蓄目標、預測任何一項載入失敗,只有那一格沒有數字,首頁其他部分照常,沒有整頁錯誤。資金指標、帳戶、當月收支與預算仍是總覽的必要資料,失敗時整頁顯示錯誤(沒有它們首頁沒有意義)。
- 入口格沿用「放得下才多欄」的欄數規則(`TileColumns`):理想寬度只算圖示與名稱,關鍵數字放不下就折行、不影響欄數;最大字級單欄,關鍵數字在最下面靠右。每格是一個按鈕,VoiceOver 念「名稱,關鍵數字」。
- 「我的」移除「設定｜規劃」分段控制(`me.page`),只剩姓名、機器人記帳、外觀、登出、版本。

## Consequences

- 到「儲蓄目標」從 3 下(頭像 → 規劃分頁 → 項目)變 1 下(首頁入口);登出、改外觀仍是 2 下。
- 首頁一次載入的請求變多(本月收支明細、儲蓄目標、公帳代墊統計):各自平行,各自失敗不影響其他。本月筆數用分頁抓齊整個月再數,資料量大時是最重的一項。
- 「信用卡」與「帳戶」入口目前都到帳戶頁,日後若信用卡有自己的畫面再分開。
- `docs/parity.md` 第 43、47、49 項更新,新增第 64 項;`DESIGN.md`「總覽」「導覽」「我的」同步;`ForecastUITests` 等從「我的」進規劃的 UI 測試與截圖巡覽改從首頁入口進。
