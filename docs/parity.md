# 功能對等清單(web → iOS)

**基準**:[`onion523/my-money@42149e7`](https://github.com/onion523/my-money/tree/42149e7)(2026-10-10)。`38f0a88`、`a09e923`、`d0424df`、`42149e7` 的同步項目見 #236(每月統計與記帳頁總額改全量加總、結帳日保留未出帳、報銷沖帳逐筆勾選、收支明細公帳三態);web 專屬的彈窗尺寸、徽章顏色與圖示、tooltip 不同步(第 67 項)。前一版基準:`718ace9`(2026-10-09)。 `b1f6067`(預測 60 天、已出帳與未出帳分開)與 `718ace9`(收支時間與詞彙)已同步;`64315ce`(web 深色調色盤)不適用。前一版基準:`029ae5e`(2026-10-05)。`79532b4` 之後的 commit(`aa57b1b`～`b1f6067`)已同步:預測起始餘額與合併的繳卡費事件(`5b2faa6`)、儲蓄目標圖示代號(`efd5064`)、機器人與轉帳訊息改純文字(`aa57b1b`、`d45f878`、`efd5064`);web 的手機版 RWD 與底部抽屜(`470ba36`)、公式提示 tooltip(`5b2faa6`、`029ae5e`)、換頁捲回頂端、懸浮記帳鈕、全站 Lucide 圖示不適用於 iOS(見第 67 項)。先前功能層同步到上游 ADR 0020:ADR 0018(預測事件勾選已繳，`2e80d4f`)、ADR 0019(收支明細帳戶篩選、信用卡週期收支現金流平移、用詞正名，`b456545`)、ADR 0020(結帳區間出帳、交易出帳狀態與延至下期，`9ac962f`～`87d941c`)。其後的 ADR 0021(`6f5fe30`，手機版總覽帳戶卡溢出)與 ADR 0022(`79532b4`，最近交易格式與折行)只動 web 版面，iOS 不受影響。行號以 `W:` 代表 `web/src/`,`B:` 代表 `backend/src/`。行號後面的 `@e138bd9`、`@c16dfcc` 是 ADR 0016、0017 的基準，`@4fbf863`(2026-10-03,#50–#55)、`@af5444c`(2026-10-02,#44–#49)、`@0db6c20`(2026-09-30,#105)、`@97f4789`(2026-09-30,#94)與 `@f32ff6c`(2026-09-29,#54)是前幾版基準，沒特別註明版本的行號，指的是更舊的基準 `43a205d`。

**規則**(ADR-0001):功能層與 web 對等，互動層照 HIG 轉譯(`DESIGN.md`),照抄程式流程,bug 不照抄。每條清單就是一項驗收標準。跟 web 不同的地方，一律列在「刻意偏離 web」,並回報給 web。舊基準的問題回報於 [onion523/my-money#1](https://github.com/onion523/my-money/issues/1)、[#2](https://github.com/onion523/my-money/issues/2);`bd0507b` 之後的問題回報於 [onion523/my-money#9](https://github.com/onion523/my-money/issues/9)(上游在 `b1382f4` 修正並關閉),`b5cbe09` 之後的問題回報於 [onion523/my-money#19](https://github.com/onion523/my-money/issues/19)(上游在 `da82a11` 修正並關閉),`f32ff6c` 之後的問題回報於 [onion523/my-money#27](https://github.com/onion523/my-money/issues/27)。

**詞彙**:以 `CONTEXT.md` 為準，UI 文字也用它的詞，用字規則見 `CONTEXT.md` 開頭：上游 `CONTEXT.md` 有定義的概念用正名;iOS 補充的詞跟 web 畫面現在的叫法;web 的疊字不照抄;wire 上的資料(系統分類名稱)、使用者資料和英文識別字不改。本檔引用的 web 畫面文字和後端訊息只用來說明現況，照原文引用，包括疊字和舊詞。

## 交易(W:pages/Transactions.tsx)

- [x] 篩選：
  - 起日預設本月 1 號，迄日預設今天，視角預設全部。這三項送到伺服器(`GET /transactions?from&to&scope`)。
  - **年月快速切換**(iOS 才有，刻意偏離第 61 項，#130):交易頁頂端的「‹ 2026年10月 ›」，一步跳到任一整月(本月是 1 號到今天，過去的月份是 1 號到月底)，等同改起迄日，不必進篩選 sheet。
  - 類型(全部、支出、收入)、分類、關鍵字只在本機過濾。關鍵字不分大小寫，比對備註、分類、帳戶名稱、記帳人。
  - iOS 的視角、起迄日、類型、分類在 toolbar 篩選按鈕打開的「篩選」sheet,按「完成」才套用，套用了非預設篩選時按鈕改成品牌粉紅的空心圓圈(不顯示範圍文字，ADR-0006、ADR-0008);搜尋欄照舊在最上面(刻意偏離第 48 項)。

## 前端常數

- 支出分類 16 種：餐飲、交通、汽機車輛、居家水電、數位訂閱、購物、生活、娛樂、美妝保養、醫療、教育、寵物毛孩、旅行度假、社交人情、保險稅費、其他。收入分類 8 種：薪資、獎金、投資、兼職、政府補貼、禮金餽贈、二手出清、其他(W:components/utils.ts@97f4789,`CATEGORIES`;原本是支出 8 種、收入 5 種，W:components/utils.ts:26-27@f32ff6c)。歷史資料不遷移。系統分類：信用卡還款、內部轉帳、ATM提款、公帳代墊報銷(`bd0507b`)。
- 週期：每月、每雙月、每季、每半年、每年，換算的月數依序是 1、2、3、6、12。
- 帳戶顏色:`#FF8A8A #FFD4A0 #A8D8EA #95E1D3 #F38181 #FCE38A #EAFFD0 #C9D6FF`(W:utils.ts:54-55)。

- 門檻值：接近上限是 80%;超支是已花大於預算。
- 在 client 算的規則：接近上限(80%)、分攤建議(差額的一半，四捨五入)、每一項週期收支的分攤平滑(`amount / 月數`)、剩餘額度(最小是 0)和目標的百分比。後端沒有這些欄位，web 也是在前端算，iOS 照 web 的算法。其餘的指標(淨可用餘額、欠款公私拆解、代墊與報銷、超支、預測、購買力試算)都用後端的值。

## 後端造成、iOS 照舊保留的行為

以下是後端的問題。後端凍結,iOS 避不開(ADR-0001),等上游修正:

1. ~~編輯或刪除交易時不回沖帳戶餘額~~:已在 `b5cbe09` 修正(交易餘額雙向連動)。信用卡的回沖在 `da82a11` 改成雙層負債回退(第 17 項),在同一張卡上編輯刷退仍有問題，見第 20 項。
2. 預測的週期判斷寫成 `month % cycle === 0`:季繳只在 3/6/9/12 月觸發，年繳只在 12 月;扣款日設 29 到 31 時，遇到較短的月份會直接跳過(B:handlers/forecast.ts:22)。
3. 資料範圍不一致:`/accounts` 和 `/accounts/balance` 依 `scope` 計算(`bd0507b`),但 `/forecast`、`/forecast/purchase-check`、`/recurring`、`/goals`、`/budgets` 和 CSV 匯出只算自己(B:forecast.ts:33,69、export.ts:13)。
4. 預算無法刪除，也無法歸零。
5. ~~任何家庭成員都能編輯、刪除其他成員的帳戶和交易~~:已在 `af5444c` 修正(上游 ADR 0013，見「帳戶」「交易」的權限項)。(~~`PUT /transactions` 不檢查新的 `account_id` 是否屬於這個家庭~~:已在 `b5cbe09` 修正。)
6. 邀請碼:`expires_at` 是 ISO 字串，卻跟 `datetime('now')` 比字串，所以到期當天整天都還算有效;邀請碼或綁定驗證碼碰撞時會回 500。
7. LINE webhook 沒有驗證簽章(`LINE_CHANNEL_SECRET` 沒有使用),Telegram webhook 也沒有 secret。
8. 儲蓄目標存入超過目標金額時，會被靜默截斷。
9. 密碼只做一輪加鹽 SHA-256;`JWT_SECRET` 沒設定時會 fallback 成 `'dev-secret-key'`。
10. `DELETE /auth/account` 沒有任何 web UI 使用，所以 iOS 依 parity 也不做(見「不做」)。**建立家庭群組的人刪除帳號時，因為 `households.created_by` 是 `ON DELETE CASCADE`,整個家庭群組和其他成員的成員關係都會一起被刪除**。
11. `POST /accounts/pay-credit-card` 沒有檢查 `bank_account_id` 是不是銀行存款帳戶，所以 API 允許從另一張信用卡「扣款」。web 只列出銀行存款帳戶,iOS 也只列銀行存款帳戶。
12. 欠款公私拆解只用這張卡最近 50 筆支出，從最新的一筆往回分配，是一種估算;如果繳過一部分卡費，拆解出來的結果不一定準確。
13. 結帳日出帳作業從 `82d9124` 起不檢查結帳日，有未出帳款就能做，所以下一期的刷卡也可能被一起轉入已出帳待繳款(已回報 onion523/my-money#2)。`da82a11` 起後端會記錄出帳作業的時間(`last_rollover_at`,B:handlers/accounts.ts@f32ff6c:265),但只用在信用卡未出帳自動校準的起點;有未出帳款就能做的條件沒變(B:handlers/accounts.ts@f32ff6c:262)。iOS 跟 web 用一樣的條件。
14. ~~現金流預測、購買力試算和機器人查餘額的起始餘額沒有算現金錢包~~:已在 `b1382f4` 修正。
